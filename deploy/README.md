# Free server deployment preparation

This is a deployment draft, not a deployed service. Oracle Always Free is a candidate; account creation normally requires card identity verification and compute capacity is not guaranteed. Do not upgrade to a paid account or provision resources outside Always Free. The user must separately and explicitly confirm an identified deployment before deployment. Never push to GitHub without separate confirmation.

The prototype can run on Node.js 24 with built-in SQLite on an Always Free Linux VM. `src/server.js` listens only on localhost port 8787 and implements the same API as the Cloudflare Worker. A reverse proxy with valid HTTPS is still required for phone uploads. No proxy or domain has been chosen, installed or verified. Do not expose the HTTP listener or private health data directly to the internet.

The two example systemd units assume a non-root `runorpay` user, source files at `/opt/run-or-pay`, private writable state at `/var/lib/run-or-pay`, and secret environment files under `/etc/run-or-pay` protected from other users. Set `DB_PATH=/var/lib/run-or-pay/run-or-pay.sqlite`, three independent random secrets, `CHALLENGE_URL` to the service's HTTPS URL, and `WHATSAPP_SESSION_PATH=/var/lib/run-or-pay/whatsapp` before use. Do not commit secrets, database files, session files or QR codes. Node.js must actually be installed at `/usr/bin/node` or the units adjusted.

WhatsApp uses Chromium with `--no-sandbox` per the experimental bridge; that weakens isolation and needs a host security review. Configure the system to run it as the dedicated non-root account. The login QR and group selection need an interactive setup process; it is not automated by these units. Install production dependencies and an arm64-compatible browser on the target VM. Browser installation, TLS, DNS, firewall rules, backups, updating and monitoring are not implemented. Source-data terms and rules for finalization remain unresolved. Never use for real penalty decisions until verified.
